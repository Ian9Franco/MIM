# Revisión técnica — 4 de septiembre de 2026

Revisión transversal del repositorio: aplicación Next.js de escritorio, subproyecto web, Electron, API, persistencia, SQL, descargas, validación de packs, rescate NBT y CI. No equivale a verificar cada interacción de UI ni el despliegue real de Supabase. No se cambiaron implementaciones.

## Hallazgos prioritarios

### 1. P1 — Borrado de proyectos permite eliminar la raíz de datos

Ubicación: `app/api/project/delete/route.ts:24-32`.

El reemplazo de caracteres no rechaza `.` ni `..`. Con `projectName: "."`, `path.join` resuelve a `_projects`; con `".."`, a `SOURCE_BASE`. Luego se aplica `rmSync` recursivo. Una petición incorrecta puede borrar todos los proyectos o toda la biblioteca. Reproducción realizada únicamente calculando rutas, sin ejecutar borrados.

Corrección: validar un nombre simple distinto de puntos, resolver contra la raíz autorizada y exigir un descendiente estricto antes de eliminar.

### 2. P1 — HTML externo conserva handlers ejecutables en web y escritorio

Ubicaciones: `web/lib/markdown.ts:76,103`; `utils/markdown.ts:204,266`.

El sanitizador web permite expresamente `onerror`. El formateador de escritorio retorna HTML sin sanitizar. Ambos conservan un `<img>` con un handler arbitrario, confirmado con una asignación inocua a `window.__reviewMarker` en el texto de salida. Las descripciones se insertan mediante `dangerouslySetInnerHTML`; un error de carga de imagen puede ejecutar el handler bajo el origen de la aplicación. En escritorio, esto es especialmente relevante porque existen APIs que modifican archivos locales.

Corrección: sanitización común y robusta para todo HTML externo, sin atributos `on*`; manejar errores de imágenes desde código propio. Añadir pruebas de regresión para ambos formateadores.

### 3. P1 — El editor de configuración permite escapar de su directorio

Ubicación: `app/api/config/files/route.ts:30-40,54-55,109-110`.

`startsWith(basePath)` valida un prefijo textual: `../config-other/example.txt` pasa para una raíz terminada en `config`. Esto afecta lectura y escritura. Además, las rutas de historial se construyen con parámetros sin verificar pertenencia a la raíz, y `project` tampoco está restringido a un segmento seguro.

Corrección: validar los segmentos de proyecto e historial y comprobar pertenencia mediante rutas relativas, incluyendo enlaces del sistema de archivos cuando corresponda. Reproducción realizada solo con cálculo de rutas.

### 4. P1 — El guardado de rescate NBT no es atómico

Ubicación: `app/api/sage/player-rescue/save/route.ts:40-56`.

Si falla el backup solicitado, el endpoint registra una advertencia y continúa. Luego escribe directamente sobre el archivo original mediante `writeFileSync`. Un fallo durante esa escritura puede dejar el archivo truncado, incluso sin backup utilizable. Los tests del parser binario no demuestran seguridad de esta operación de persistencia.

Corrección: abortar si no se puede producir el backup requerido; escribir y verificar un temporal en el mismo directorio antes de reemplazar el original.

### 5. P2 — El rate limiter mezcla cuotas de endpoints diferentes

Ubicaciones: `lib/apiGuard.ts:76-80`, `web/lib/apiGuard.ts:61-65`, `lib/rateLimiter.ts:46-50`.

La clave por defecto es únicamente la IP. Todos los handlers que comparten la instancia del módulo consumen el mismo contador aunque sus límites sean diferentes. Reproducción: 20 peticiones bajo una cuota de 60 provocan que la primera petición bajo una cuota de 20 sea rechazada. En uso normal, la navegación puede agotar la cuota del explicador o traductor sin haberlos utilizado. El alcance concreto depende de cómo el despliegue agrupe las instancias.

Corrección: identificar explícitamente la política o endpoint en la clave; si se desea un límite global, aplicarlo separadamente con reglas uniformes.

### 6. P2 — Los enlaces de protocolo no se normalizan en un arranque en frío

Ubicación: `standalone/main.js:146-148`, `105-106`.

Cuando la app ya está abierta, `handleDeepLink` convierte `mim://` en una URL HTTP local. Al iniciar desde cero, se guarda la URL `mim://` directamente y se pasa a `loadURL`, sin esa conversión. No existe un handler de contenido Electron registrado para servir ese esquema. El enlace no llega al mismo flujo que una segunda instancia.

Corrección: pasar el enlace inicial por la misma normalización que los eventos posteriores, antes de crear la ventana. Hallazgo de lectura de código; no se lanzó el instalador.

### 7. P2 — DAST da éxito cuando no pudo auditar y no bloquea CI

Ubicación: `scripts/security/dast-scan.js:110-144`; `.github/workflows/ci.yml`.

Se ejecutó contra `http://127.0.0.1:1`, sin servicio. Ambas conexiones fallaron y aun así imprimió `PASSED (Zero critical findings)` con salida 0. Tampoco establece una salida de fallo si encuentra problemas. El job de CI usa por defecto una URL desplegada, sin levantar ni probar la revisión actual. Los comandos de ZAP y Nuclei solo se imprimen; no se ejecutan.

Corrección: distinguir fallo, resultado inconcluso y éxito; hacer fallar el job según una política explícita y auditar una instancia de la revisión que se está verificando.

### 8. P2 — El validador confunde versiones por prefijo

Ubicación: `lib/modding/packValidator.ts:112-119`.

La comparación bidireccional con `startsWith` considera compatibles `1.21.1` y `1.21.10`. Son versiones distintas y la regla preventiva no emite el aviso que corresponde. El comentario menciona rangos, pero tampoco se interpretan como tales.

Corrección: comparar componentes completos y procesar rangos explícitamente; no usar prefijos de texto para versiones exactas.

## Límites y observaciones

No se ejecutaron borrados reales, rescates sobre mundos, envíos a terceros ni migraciones SQL. Las políticas SQL fueron inspeccionadas como archivos, sin contrastarlas con la base desplegada. No se realizó una auditoría de vulnerabilidades de dependencias ni una prueba completa de interfaz o del instalador.

El build de producción presentó advertencias de trazado standalone: intentó copiar rutas externas de `D:/.MIM/source/.mim-index` a un destino que incorpora otro `D:` dentro de `.next/standalone`, produciendo `ENOENT`. `next.config.ts` excluye otra ruta (`D:/.mine/source`). Conviene corregir el alcance del trazado y verificar el paquete en un equipo sin los datos del desarrollador; compilar no certifica que el instalador esté completo.

Prioridad sugerida: resolver primero borrado, HTML externo y límites de rutas; después persistencia NBT, fiabilidad de los controles y fallos funcionales.
